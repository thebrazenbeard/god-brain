## Problem

The repository is now God Brain, but two inherited HC surfaces still speak as if the repository itself is the canonical Hyperconnectome Brain project:

- `docs/REPOSITORY_MAP.md` opens with `# Hyperconnectome Brain Repository Map` and states that “this repository defines the reusable HC-series Hyperconnectome Brain template”;
- the same map treats `WARDEN.md` as current repository authority and labels Noah/Four/Vera as current project roles;
- `WARDEN.md` grants Noëtarch / Noah direct-main and canonical-integration authority for the **Hyperconnectome Brain project**.

Those statements are valid predecessor-lineage evidence. They are not automatically God Brain currentness or God Brain authority.

Therefore:

`HC_PREDECESSOR_GOVERNANCE != GOD_BRAIN_GOVERNANCE`

`HC_SUBSTRATE_CANON != COMPLETE_GOD_BRAIN_CANON`

`INHERITED_ROLE_AUTHORITY != CURRENT_GOD_BRAIN_EFFECT_AUTHORITY`

## Rebinding objective

Make repository-level entrypoints tell the truth about the current project without erasing or rewriting the HC lineage.

The intended relationship is:

`GOD_BRAIN = HC_SUBSTRATE + GOD_BRAIN_SYNTHESIS + PORTFOLIO_ADMISSION + GOD_BRAIN_CURRENTNESS/GOVERNANCE`

not:

`GOD_BRAIN = RENAMED_HC`

and not:

`GOD_BRAIN = EVERY_OTHER_REPOSITORY_AT_RUNTIME`

## Proposed treatment of docs/REPOSITORY_MAP.md

The path `docs/REPOSITORY_MAP.md` should remain the current repository map because it is the obvious repository-level navigation surface.

Future rebinding should preserve the useful HC inventory but change the referent of the document.

> This repository is the God Brain research and engineering project. Its initial cognitive substrate is inherited from the HC-series Hyperconnectome Brain architecture. HC files remain authoritative for the HC substrate within their declared scope, but HC predecessor governance/currentness does not automatically define God Brain governance/currentness.

Required distinctions near the top:

`GOD_BRAIN_REPOSITORY != HC_REPOSITORY_LINEAGE_ONLY`

`HC_ARCHITECTURE_FILE != WHOLE_GOD_BRAIN_MISSION`

`HC_QUALIFICATION_RECORD != FRESH_GOD_BRAIN_QUALIFICATION`

`HC_ROLE_CONTRACT != GOD_BRAIN_ROLE_CONTRACT`

## Proposed God Brain governance contract

A future God Brain governance document should encode the actual current division without borrowing authority from HC predecessor roles.

Minimum semantics:

### Owner authority

Patrick remains final authority for protected/canonical effects where required.

No review result, historical branch, worker role, inherited Warden grant, or coordinator self-assertion creates merge/deploy/provider/credential/canonical-effect authority.

### God Brain Coordinator

Owns:

- project meaning and thesis;
- God Brain architectural synthesis;
- portfolio admission decisions;
- provenance / source-lineage integrity;
- repository coherence;
- main-readiness assessment;
- bounded integration candidate preparation;
- reconciliation of BT2 evidence into God Brain.

Does not gain merge authority merely from coordination ownership.

### BT2 Coordinator

Owns:

- worker reconstruction and dispatch;
- independent review;
- adversarial testing;
- bounded implementation assignments;
- qualification evidence;
- engineering workforce coordination.

BT2 evidence informs God Brain integration; it does not automatically promote content to canon.

### Collision rule

Before delegation, bind:

- repository;
- exact head/ref;
- exact files or semantic subject;
- allowed effects;
- prohibited effects;
- required evidence;
- return format.

Once delegated:

`DELEGATED_SUBJECT = BT2_OWNED_UNTIL_RETURN_OR_EXPLICIT_CANCELLATION`

God Brain Coordinator must not independently mutate that same subject.

### Main discipline

`REVIEW_PASS != MAIN_PROMOTION`

`PR_OPEN != MAIN_PROMOTION`

`MERGEABLE != MERGE_AUTHORITY`

Prefer the smallest coherent main-bound unit, unless multiple independently reviewed units have currentness dependencies that make one atomic bundle safer.
