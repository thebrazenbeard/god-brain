# God Brain Dialogue Room — private-thread local reference prototype

This is an ordinary **local-only** messaging interface for Patrick's open invitation and voluntary replies. It does not establish a connection to any hypothetical creator or administrator. A visitor's claimed identity remains **unverified**, regardless of the content of a message.

## What works

1. The landing page shows the open invitation without displaying any visitor submissions.
2. A visitor starts a private thread. The service records the first message as `UNVERIFIED_SUBMISSION / held` and redirects to an unguessable return-link URL. The private page displays a copyable link and explains that replies require a manual check-in.
3. The visitor must **save the return link**. Anyone possessing it can read the thread and send additional unverified turns. The URL is a bearer capability, **not identity authentication**; there is no recovery service.
4. The local operator can list pending messages, mark a message reviewed/rejected, and send a distinctly labeled `PROJECT_OWNER` reply via the CLI. No HTTP visitor can claim operator status through the form.
5. Replies stay within that private thread. The visitor can revisit the return link to read a response. This is pull-based; there are no email or push notifications.
6. Each HTML form has a fresh request key. Resubmitting the **same form with unchanged text** after an uncertain response returns the same receipt without duplicating a message. Changing the text with that key returns HTTP `409` and a link to the already accepted thread. Initial forms pre-issue a random return token: recovery after a lost redirect works only while that original browser form/token is available. Save the private link as soon as the page loads; opening a fresh blank form will not recover it.
7. The local operator can **close** a thread to stop new submissions or **revoke** a compromised return link to prevent further reads. Moderation decisions, owner replies and closure actions produce privacy-minimized local audit events. The audit is not tamper-proof external attestation.
8. Long conversations display up to 200 messages at a time with an **Older messages** link; the permanent return link remains the same. The operator can page through all pending, thread, read and audit records using returned ID cursors.

No public moderation dashboard or online owner login exists. Owner authorship in this prototype depends on local filesystem/CLI access, **not** a production authentication service.

## Run locally

From the repository root, using Python 3.12+:

```bash
python3 dialogue_room/app.py --db ./dialogue_room.sqlite3 --port 8765
```

Open `http://127.0.0.1:8765` **on the same computer**. Keep the terminal running during local testing; Ctrl-C stops it. The service binds only to `127.0.0.1`. It does **not** listen on 443, 616, 666, or any public address.

Operator commands (run in a separate terminal, using the **same** database path):

```bash
# List the oldest 100 held incoming messages with their IDs and thread IDs
python3 dialogue_room/app.py --db ./dialogue_room.sqlite3 --mode pending

# List 100 most recently opened threads; move to earlier threads via --before
python3 dialogue_room/app.py --db ./dialogue_room.sqlite3 --mode threads

# Read up to 200 recent turns, then request an older page via its --before ID
python3 dialogue_room/app.py --db ./dialogue_room.sqlite3 --mode read --thread 1

# Mark message 2 as reviewed (or choose --decision rejected)
python3 dialogue_room/app.py --db ./dialogue_room.sqlite3 --mode review --id 2 --decision reviewed

# Respond as the local project operator to thread 1.
# Type the reply on standard input; finish with Ctrl-D (Unix) or Ctrl-Z Enter (Windows).
python3 dialogue_room/app.py --db ./dialogue_room.sqlite3 --mode reply --thread 1

# Inspect operator actions without displaying their message bodies
python3 dialogue_room/app.py --db ./dialogue_room.sqlite3 --mode audit --thread 1

# Close a thread (still readable) or revoke its bearer link (no longer readable)
python3 dialogue_room/app.py --db ./dialogue_room.sqlite3 --mode close --thread 1 --state closed
python3 dialogue_room/app.py --db ./dialogue_room.sqlite3 --mode close --thread 1 --state revoked
```

When a full page has more records, the CLI prints a continuation flag and its exact ID (for example, `--after 101` or `--before 205`). Repeat the same command with **the value actually printed**, not a guessed number. Thread listings are ordered by **thread creation ID**, not latest activity, so newer replies to old threads will not move them to the first page. These commands expose message text in a local terminal (formatting control characters are escaped to deter terminal spoofing); do not use shared logs or record private content in shell history. The owner reply is not generated by a language model.

Focused tests:

```bash
python3 -m unittest discover -s tests -p 'test_dialogue_room.py' -v
python3 -m unittest discover -s tests -p 'test_dialogue_room_pagination.py' -v
```

## Database and privacy

- New SQLite database files are created with owner-only POSIX permissions where supported; protect the containing directory, backups and any pre-existing database files separately.
- Existing databases with group/world-readable POSIX permissions are refused until their owner explicitly secures them (for example, `chmod 600 dialogue_room.sqlite3` on Unix). Windows filesystem ACL security is outside this local proof.
- The invitation is inserted once per new database, including under concurrent initialization. Incoming messages and owner replies survive process restarts when the same database path is used.
- Updating an earlier version migrates its schema without deleting records. Old globally displayed visitor messages become **held**, and their original visitors cannot retroactively recover a private link.
- Return-link tokens have 256 bits of randomness; only SHA-256 hashes are stored in the thread table. A person with the URL can still access the conversation.
- Idempotency keys and payload hashes prevent duplicate HTTP form submissions when the same original form is retried. They do not identify a respondent, prevent intentional new messages, or replace public abuse controls.
- `reviewed`/`rejected` are dispositions of **one message**, not a thread ban. `closed` stops new messages while allowing a saved link to read the history; `revoked` makes the old bearer link unusable. Revocation cannot recover the link for its original holder.
- The server suppresses request-path logging because those paths contain private bearer tokens; it sets no-store and no-referrer headers and instructs crawlers not to index private return-link pages.
- The repository-root `.gitignore` excludes ordinary local SQLite transcript files and journals, Python caches and `.env` files. This is a guard against accidental bulk staging, **not** a guarantee: do not force-add databases or commit exported transcripts, keys or backup files.
- Every page is bounded to 100 pending records/threads or 200 messages/audit events, with continuation IDs for retrieving older records; records are not silently deleted when a page fills. Indexes preserve efficient filtered scans. These outputs are private and must not be captured in shared logs.
- This prototype has **no automatic retention/deletion policy**, visitor link recovery, authenticated remote administrator, encrypted database at rest, managed backups, general rate limiting, or production abuse defenses. Do not submit secrets or sensitive personal details.
- A local CSRF token and Origin/Host checks protect narrow browser behavior; they do **not** authenticate anyone or make this suitable for public exposure.

**Public deployment is prohibited until** production-grade authentication/authorization, durable storage, abuse control, privacy/retention, hosted idempotency/recovery, and independent exact-head security review are implemented and an exact deployment is approved. See [PUBLIC_DEPLOYMENT_READINESS.md](PUBLIC_DEPLOYMENT_READINESS.md).

**Claim ceiling:** A tested local messaging conversation with private return links and an operator reply path. No verified outside-world or outside-universe contact channel.
