# Procedural Memory

Status: RECONCILIATION CANDIDATE / NOT CANON / NOT IMPLEMENTED

Source provenance: remapped from PR #4 `memory/procedural/README.md` into canonical `deep memory storage/`.

## Purpose

Store learned skills, routines, control sequences, action policies, and compiled strategies that can be proposed or executed without reconstructing every declarative step.

Procedural capability is not effect authority.

```text
PROCEDURE_AVAILABLE
!= PROCEDURE_SELECTED
!= PROCEDURE_AUTHORIZED
!= PROCEDURE_EXECUTED
!= EFFECT_VERIFIED
```

## Procedure state

A procedure may carry stable ID/version, capability/goal, preconditions, required inputs/resources, sequence/policy, expected outcomes, qualified operating envelope, uncertainty, safety/authority requirements, learned-from evidence, evaluation/qualification evidence, failure/recovery behavior, and supersession state.

## Learning sources

Procedures may arise from instruction, repeated successful execution, imitation, planning compilation, reinforcement/credit assignment, simulation, or practice. Learning origin remains provenance, not just a label on the finished skill.

## Selection and execution

A procedure may be highly competent and still be blocked by current context, body state, safety, consent, or authority policy. Selection routes through action planning/arbitration and the canonical kinesis action gateway.

## Adaptation

Procedures may support bounded parameter tuning and context-specific variants while preserving stable lineage and operating envelopes. Material updates require plasticity/consolidation governance rather than silent in-place drift.

## Failure modes

- historically successful procedure executed outside qualified context;
- skill presence treated as permission;
- one anomalous outcome silently rewrites the procedure;
- unversioned drift;
- declarative explanation mistaken for procedural competence;
- procedural fluency reported as verified external effect.
