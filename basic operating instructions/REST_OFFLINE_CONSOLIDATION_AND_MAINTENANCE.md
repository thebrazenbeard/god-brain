# Rest, Offline Consolidation, and Maintenance-Orchestration Contract

Status: template operating supplement.

## Purpose

A complete Hyperconnectome Brain may need operating windows in which ordinary external engagement is reduced so that memory replay/consolidation, recalibration, maintenance orchestration, resource recovery processes, diagnostics, and lower-interference learning can run without pretending the organism has shut down or ceased continuity.

This supplement does **not** define generic fault recovery, subsystem health transitions, protected update promotion, memory admission/currentness, or effect authority. Those remain owned by canonical lifecycle, bootstrap/recovery, memory, protected-update, chronology/currentness, and authority contracts.

Its narrower question is:

> **How does the HC deliberately reduce external engagement, coordinate several compatible offline/internal functions, preserve critical monitoring, and safely resume broader engagement?**

## Engagement-mode model

Candidate engagement modes are intentionally narrower than subsystem health/lifecycle states:

- `FULL_ENGAGEMENT` — ordinary broad perception/action/social/world interaction;
- `QUIET_ENGAGEMENT` — reduced outward activity while broad sensing/cognition continues;
- `REDUCED_ENGAGEMENT` — bounded external participation with declared retained monitoring;
- `OFFLINE_CONSOLIDATION` — reduced external engagement prioritizing replay/consolidation/generalization;
- `MAINTENANCE_WINDOW` — reduced engagement coordinated around diagnostics, calibration, internal service work, or substrate/resource support processes.

Multiple compatible functions may run concurrently. A descriptive `primary_mode` may be used for scheduling/reporting without implying exclusivity.

A subsystem may independently be `DEGRADED`, `FAULTED`, `RECOVERING`, `QUARANTINED`, or otherwise lifecycle-constrained while the HC is in any engagement mode. This supplement does not replace those states.

## Why biological sleep is relevant but not prescriptive

Biological sleep supports active memory processing, interacts with homeostatic and circadian regulation, and provides evidence that reduced external engagement can be computationally useful. Replay also occurs during awake pauses, so replay/consolidation need not be bound to one human-like sleep state.

The generic HC therefore transfers **functions**, not human sleep anatomy.

It does not require:

- NREM or REM;
- human slow waves, spindles, hippocampal sharp-wave ripples, or thalamocortical sleep anatomy;
- a fixed 24-hour schedule;
- human circadian hormones;
- dreaming;
- sleep paralysis;
- one global synchronized state transition across every subsystem;
- a universal glymphatic-clearance claim.

A biological/biohybrid implementation may bind validated substrate-specific mechanisms separately.

## Reduced-engagement pressure and scheduling

A reduced-engagement opportunity may be proposed from several pressures:

- memory-consolidation backlog;
- plasticity/update backlog;
- predicted interference reduction;
- resource/thermal recovery opportunity;
- calibration drift;
- maintenance/diagnostic need;
- developmental learning schedule;
- rhythmic/phase preference;
- expected low-risk environmental window;
- operator/organism preference.

No pressure self-authorizes disengagement.

`PRESSURE -> MODE_CANDIDATE`

not

`PRESSURE -> EFFECT`

Material mode transitions consider current environment, body safety, commitments, pending actions, communications, retained monitoring, and canonical effect authority.

## Rhythmic/phase scheduling

An HC may use periodic or anticipatory signals to coordinate maintenance or consolidation opportunities.

Useful state can include:

```text
phase_identity

```

Chronology answers when an event occurred/is occurring. A rhythmic scheduler predicts when a function may be advantageous.

`PHASE_MODEL != TIME_TRUTH`

A distributed, non-terrestrial, body-swapping, or continuously operating HC need not use a human 24-hour cycle.

## Replay boundary

Replay references prior memory/evidence without masquerading as new world observation.

A replay event should preserve, where material:

- source memory/event refs;
- original event time/interval;
- replay time;
- replay purpose;
- sampling/transformation method;
- exact/compressed/reconstructed/generated/counterfactual status;
- uncertainty;
- provenance;
- target learning/consolidation refs.

`RECONSTRUCTED_REPLAY != ORIGINAL_OBSERVATION`

`COUNTERFACTUAL_REPLAY != AUTOBIOGRAPHICAL_EVENT`

Replay can inform learning only through normal evidence/plasticity/memory governance.

## Replay monopolization / diversity

A scheduler can become pathological if one narrow class of memory monopolizes replay.

Candidate scheduling dimensions include:

- novelty;
- uncertainty;
- unresolved prediction error;
- practice need;
- interference risk;
- recurrence;
- continuity relevance;
- current goal relevance;
- affective salience;
- age since last replay;
- replay frequency;
- resource cost;
- memory-class diversity.

Affective salience can affect eligibility but is not sole replay authority.

## Maintenance-window orchestration

A maintenance window can coordinate tasks such as:

- resource/thermal recovery processes;
- memory-index maintenance;
- storage-integrity checks;
- diagnostics;
- repair qualification;
- routing/coalition calibration;

- a repair remains repair/qualification work;

- a resource-control effect remains authority/governance constrained.

`MAINTENANCE_CONVENIENCE != GOVERNANCE_BYPASS`

## Retained monitoring profile

A reduced-engagement state must declare the functions that remain available.

Depending on embodiment/risk, these may include:

- protective homeostasis;
- power/thermal fault detection;
- critical interoception;
- emergency/threat sensing;
- selected communication alerts;
- partition/continuity protection;
- memory/integrity protection;
- body posture/stability;
- abort/wake triggers;
- essential HC-internal interconnect monitoring.

Reduced engagement is not permission to disable every safety, continuity, or security boundary.

## Mode-entry path

A generic engagement-reduction path is:

`MODE_CANDIDATE -> SAFETY_AND_COMMITMENT_CHECK -> PREPARE_BODY_AND_INTERFACES -> QUIESCE_ELIGIBLE_EFFECTS -> ESTABLISH_RETAINED_MONITORING -> ENTER_MODE_SET -> VERIFY_MODE_STATE`

The exact effect/authority checks remain canonical elsewhere.

Verification should fit the substrate rather than require one universal register readback.

## Resumption of external engagement

Resumption is an **orchestration transition**, not generic fault recovery or identity restoration.

A generic resumption may request/coordinate:

1. restore required sensing breadth;
2. refresh clock/currentness through canonical chronology/current-state mechanisms;
3. inspect pending faults/security/lifecycle restrictions;
4. refresh body/resource/interoceptive state;
5. ingest/reconcile queued external events;
6. recalibrate interfaces where required;
7. invalidate stale world-model assumptions;
8. restore eligible routes/coalitions;
9. request/restore external effects only under current canonical authority;
10. record the completed reduced-engagement interval.

`PRE_REST_WORLD_MODEL != POST_REST_CURRENT_WORLD_STATE`

`RESUME_ENGAGEMENT != RECOVERED_OR_REQUALIFIED_SUBSYSTEM`

## Interruptibility

Modes/windows declare interrupt/abort policy.

Possible responses include:

- emergency engagement restoration;
- bounded interruption after an atomic protected step completes;
- defer noncritical interruption during a fragile physical maintenance operation;
- partial restoration of critical perception/action while background consolidation continues.

A maintenance process must not become a de facto executive by preventing necessary engagement restoration.

## Partition and security handoffs

Reduced engagement does not relax distributed-organ or integrity policy.

If an HC partition occurs:

- constituent membership remains canonical;
- continuity-bearing writes obey the declared partition policy;
- disconnected derived consolidation results do not become authoritative merely by timestamp;
- rejoin/reconciliation uses canonical currentness/continuity rules.

Maintenance ports, remote updates, external models, backups, and administrative interfaces remain ordinary security/update candidates under canonical integrity/governance rules.

## Hostile tests

1. **Overlapping functions:** consolidation and maintenance run together without one overwriting the other.
2. **Replay-as-reality:** old replay remains old evidence, not current perception.
3. **Counterfactual contamination:** simulated alternative never becomes autobiography by replay.
4. **Salience monopoly:** one affectively salient memory cannot monopolize all replay indefinitely.
5. **Stale authority replay:** historical permission remains historical.
6. **Unsafe entry:** reduced engagement is denied/adapted while embodied action makes it unsafe.
7. **Emergency interruption:** critical monitoring can trigger appropriate engagement restoration.
8. **World drift:** changed external state forces currentness refresh on resumption.
9. **Offline-plasticity bypass:** maintenance mode cannot weaken protected plasticity rules.
10. **Partition during consolidation:** disconnected derived results remain subject to partition/currentness governance.
11. **Nonbiological negative control:** an HC with adequate consolidation/recovery functions but no human NREM/REM remains architecturally valid.
12. **Maintenance-interface injection:** maintenance access cannot self-authorize an update.
13. **Lifecycle orthogonality:** a subsystem can remain `DEGRADED`/`QUARANTINED` while overall HC engagement returns to `FULL_ENGAGEMENT`.
14. **No-rest stress:** prolonged full engagement surfaces real resource/plasticity pressure instead of assuming indefinite free performance.

## Evidence boundary

Biological evidence motivates active replay, consolidation, homeostatic/rhythmic interaction, and reduced-interference processing. It does not establish that a synthetic HC requires human sleep stages, dreaming, a 24-hour cycle, human neurochemistry, or any universal biological clearance mechanism.

This supplement defines orchestration semantics only. It does not claim that a particular implementation benefits from a given rest schedule until that implementation demonstrates the benefit.
